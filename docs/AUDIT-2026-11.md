## Findings

Status: **Fixed** = implemented with tests in this audit; **Open** = still to do.

### Critical

| # | Finding | Status |
| --- | --- | --- |
| C1 | Workflow script injection: `prepare-release.yaml`, `main-outputs.yaml` and `dev-preview.yaml` put free-text dispatch inputs (`revision_description`, `source_label`, `target_branch`, `source_sha`) into bash via `${{ }}`. Anyone able to dispatch could run code with `contents: write`. | Fixed: inputs go through `env`. Guarded by `test_release_workflows`. |
| C2 | Published fabrication outputs were not tied to the accepted outputs. `release.yaml` rebuilt everything from the tag using a moving `v2_dk9` image, with no hash evidence. | Fixed: accepted manifest committed at prepare and verified at publish; hashed `MANIFEST.txt`. |
| C3 | No control stopped a changed PCB from being released under an existing PCB revision, and nothing showed a documentation-only release reused the approved fabrication baseline. | Fixed: fingerprints, impact rules, ledger. See `RELEASE_MODEL.md`. |

### High

| # | Finding | Status |
| --- | --- | --- |
| H1 | `_remote_tag_exists` returned "absent" on timeout or any `git ls-remote` failure. A network failure read as "tag free". | Fixed: tri-state `remote_tag_state`. Unknown blocks the release. |
| H2 | Prepare checked tags after pushing the release commit to `main`. A tag collision left a released state on `main` with no tag. | Fixed: checked before any push. A tag push failure prints recovery commands. |
| H3 | Prepare released whatever `main` was at dispatch time, not the reviewed commit. | Fixed: `source_sha` input (filled from the accepted state in TUI/CLI) is verified. The non-forced push also fails if `main` moved. |
| H4 | `kibot_launch.sh` used `eval` on strings built from `--variant`/`--version`, ignored KiBot exit codes, and fell back silently to `all_group` for any non-9 KiCad. | Fixed: argv arrays, validated variant, exit codes propagate, explicit 9/10 selection. |
| H5 | A human tag push and the dispatch could both start `release.yaml`, and re-runs could overwrite a published release's assets. | Fixed: per-tag concurrency and refusal to modify a published release. (The bot's own tag push uses `GITHUB_TOKEN` and does not trigger workflows, so a duplicate needed a manual push or a PAT.) |

## Hypotheses not confirmed

- That KiCad 10 outputs differ materially from KiCad 9 outputs for this
  template. This needs `kicad-compat.yaml` runs on a real project. It was not
  dispatched.
- That KiBot `v2_dk10` handles every output in `all_group_k10`
  (ODB++, Blender renders, KiRI). Upstream documents KiCad 10 support, but this
  audit did not verify it.
