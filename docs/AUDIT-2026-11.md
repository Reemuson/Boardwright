# Engineering Audit — November 2026

## Baseline

| Item | Value |
| --- | --- |
| Local branch / commit | `main` @ `126d279`, 16 commits ahead of `origin/main` (`4933c47`) |
| Working tree | 47 modified and 7 untracked paths of in-progress work. Snapshot: `refs/backup/pre-audit-2026-11-17` |
| Audit branch | `audit/release-model-k10` (created in place; uncommitted work preserved) |
| Environment | Windows 11, Python 3.14.3, Textual 8.2.4. No local `kicad-cli`/`kibot`; Docker daemon not running. |

The local tree had already resolved several remote-era concerns:
`DRAWING_REVISION`, `BOARD_REVISION` and `RELEASE_VERSION` were separate,
and revision-table rows came from `document_revisions.yaml` rather than
`CHANGELOG.md`.

## Findings

Status: **Fixed** = implemented with tests in this audit; **Open** = still to do.

### Critical

| # | Finding | Status |
| --- | --- | --- |
| C1 | Workflow script injection: `prepare-release.yaml`, `main-outputs.yaml` and `dev-preview.yaml` put free-text dispatch inputs (`revision_description`, `source_label`, `target_branch`, `source_sha`) into bash via `${{ }}`. Anyone able to dispatch could run code with `contents: write`. | Fixed: inputs go through `env`. Guarded by `test_release_workflows`. |
| C2 | Published fabrication outputs were not tied to the accepted outputs. `release.yaml` rebuilt everything from the tag using a moving `v2_dk9` image, with no hash evidence. | Fixed: accepted manifest committed at prepare and verified at publish; hashed `MANIFEST.txt`. |
| C3 | No control stopped a changed PCB from being released under an existing PCB revision, and nothing showed a documentation-only release reused the approved fabrication baseline. | Fixed: fingerprints, impact rules, ledger. See `RELEASE_MODEL.md`. |

### High

| # | Finding | Status |
| --- | --- | --- |
| H1 | `_remote_tag_exists` returned "absent" on timeout or any `git ls-remote` failure. A network failure read as "tag free". | Fixed: tri-state `remote_tag_state`. Unknown blocks the release. |
| H2 | Prepare checked tags after pushing the release commit to `main`. A tag collision left a released state on `main` with no tag. | Fixed: checked before any push. A tag push failure prints recovery commands. |
| H3 | Prepare released whatever `main` was at dispatch time, not the reviewed commit. | Fixed: `source_sha` input (filled from the accepted state in TUI/CLI) is verified. The non-forced push also fails if `main` moved. |
| H4 | `kibot_launch.sh` used `eval` on strings built from `--variant`/`--version`, ignored KiBot exit codes, and fell back silently to `all_group` for any non-9 KiCad. | Fixed: argv arrays, validated variant, exit codes propagate, explicit 9/10 selection. |
| H5 | A human tag push and the dispatch could both start `release.yaml`, and re-runs could overwrite a published release's assets. | Fixed: per-tag concurrency and refusal to modify a published release. (The bot's own tag push uses `GITHUB_TOKEN` and does not trigger workflows, so a duplicate needed a manual push or a PAT.) |

### Medium

| # | Finding | Status |
| --- | --- | --- |
| M1 | `release.yaml` "Generate revision table variables" used `if: env.KIBOT_VARIANT != 'DRAFT'` before the variable was set, and ran without installing Boardwright. | Fixed: moved after variant selection, with an install step. |
| M2 | TUI release checklist logic lived in `tui.py`. The CLI dry run showed different facts. | Fixed: both render `impact.format_impact`. The TUI also checks impact. |
| M3 | Test workspaces under the repo root leaked on Windows (read-only Git objects), so later runs collided. | Fixed for the release tests: temp dirs plus chmod-on-error cleanup. Other test modules using `Path.cwd()` workspaces should follow. |
| M4 | TUI CI poller raised `RuntimeError: Event loop is closed` when the app quit mid-poll. | Fixed. |
| M5 | `boardwright.kicad_pcb` title block still has `(rev "${REVISION}")`. `REVISION` is an empty legacy variable; the worksheets use `${DRAWING_REVISION}`, so nothing visible is wrong. | Open: authored source left untouched. Change to `${PCB_REVISION}` in KiCad when convenient. |
| M6 | PCB worksheets show only the fabrication drawing revision, not the physical PCB revision. | Open: `${PCB_REVISION}` now exists. Adding it to worksheets is a design decision. |
| M7 | `docker_kibot_linux.sh` mounts `/etc/shadow` into the container and defaults to a KiCad 8 `:dev` image. | Open: not changed without the ability to test the interactive container. |
| M8 | `INTI-CMNB/KiBot@v2_dk9` is a moving tag. | Open by decision: manifest verification now detects drift between prepare and publish. Pinning to a SHA (`01c0008`) is possible but stops automatic updates. |

### Low

| # | Finding | Status |
| --- | --- | --- |
| L1 | Fonts: Arimo and Tinos embed SIL OFL 1.1, and `LICENSES/OFL-1.1.txt` is shipped. No redistribution concern found. | No action |
| L2 | `kicad_tables.py` edits KiCad files with regex on text blocks, not a parser. It was reviewed for this audit's scope only. The new analysis code uses a read-only S-expression parser (`sexpr.py`) and never writes KiCad files. | Open: consider moving `kicad_tables.py` to the parser. |

## Hypotheses not confirmed

- That KiCad 10 outputs differ materially from KiCad 9 outputs for this
  template. This needs `kicad-compat.yaml` runs on a real project. It was not
  dispatched.
- That KiBot `v2_dk10` handles every output in `all_group_k10`
  (ODB++, Blender renders, KiRI). Upstream documents KiCad 10 support, but this
  audit did not verify it.
