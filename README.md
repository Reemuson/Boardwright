Boardwright is a KiCad/KiBot project template with a small command-line and TUI
workflow around it. It is meant for PCB projects where design review,
manufacturing outputs, and releases should be repeatable and boring.

The normal loop is:

```text
edit in KiCad -> record changes -> commit + push -> generate preview -> review artifacts -> accept to main -> create release
```

Boardwright does not replace KiCad, KiBot, git, or GitHub Actions. It gives
them a stricter handoff: clear current state, explicit next action, reviewed
outputs before promotion, and CI-owned release packages.

## Status

Boardwright is usable, but still in template/productization work.

Working today:

- local `boardwright` CLI entry point
- Textual TUI workflow cockpit with console fallback
- changelog recording and revision-history variable generation
- validation and doctor checks
- manual preview CI dispatch
- preview artifact review/fetch
- accepted-output promotion to `main`
- CI-owned release preparation and tag publishing
- KiBot output cleanup for preview, accepted-output, and release packages
- configurable project metadata, worksheet logo, legal notice, and variants
- schematic generation helpers for revision-history sheets, one-sheet

- curated source-package creation for release archives

Still being tightened:

## What Is In This Repository

```text
.boardwright/              Boardwright project metadata
.github/workflows/         Preview, accepted-output, and release workflows
assets/                    Logo assets plus generated render/3D locations
boardwright_resources/     KiBot YAML, report templates, scripts, fonts, colors
docs/                      Public spec, roadmap, TODO, provenance, testbench notes
meta/                      KiCad template metadata
scripts/                   Local install/helper scripts
src/boardwright/           Boardwright CLI/TUI Python package
Templates/                 KiCad worksheet/title-block templates
tests/                     Python regression tests
```

Full KiBot output trees such as `Manufacturing/`, `Schematic/`, `Reports/`,
`HTML/`, `KiRI/`, and `Testing/` are generated by CI. They are uploaded as
preview, accepted-output, or release artifacts, and preview builds may also
publish them to the disposable `preview` branch. They should not live on normal
source branches. Accepted and release workflows may commit only intentional
lightweight snapshot files, such as the generated project README and board
render images.

## Quick Start

From the repository root:

```powershell
.\scripts\install_boardwright.ps1
boardwright
```

The installer also installs the bundled Arimo and Tinos fonts for the current
user so KiCad can render the template sheets locally the same way CI renders
them. Restart KiCad after installing if it was already open. Use `-NoFonts` if
you only want to install the Python tooling.

For a project-local install:

```powershell
.\scripts\install_boardwright.ps1 -Scope Project
.\boardwright.ps1
```

The project-local path keeps a hardware project pinned to the tooling checked
into that project. The global command can also be configured to prefer the
nearest project-local install before falling back to the user/global install:

```powershell
.\scripts\install_boardwright.ps1 -Scope Project -InstallProfileCommand
```

Plain `boardwright` opens the TUI. If Textual is not installed, Boardwright
prints a console status view and an install hint.

For local development and template work, install the extras that include the
TUI and template helpers:

```powershell
python -m pip install -e ".[dev]"
```

## Workflow

1. Work in KiCad and project files on `dev`.
2. Open `boardwright`.
3. Record a changelog entry.
4. Commit and push to `dev`.
5. Generate a preview for the selected variant.
6. Fetch and review the preview artifact.
7. Accept the reviewed source SHA to `main`.
8. Create a draft, prerelease, or release when ready.

Main TUI actions:

- Record Changes
- Commit + Push
- Generate Preview
- Review Artifacts
- Accept to Main
- Create Release
- Project Info
- Refresh

The CLI/TUI share the same plumbing for validation, git status, workflow
dispatch, revision-history variables, and artifact review.

## Branch And Release Model

```text
dev      normal design/source branch
preview  disposable generated preview branch
main     reviewed accepted project state
tags     immutable release package points
```

Preview CI is manually dispatched and does not mutate `dev`.

Accept to Main builds from the exact reviewed `dev` source SHA. It can push the
accepted source plus the generated README/render snapshot to `main`.

Release preparation is CI-owned. It promotes the changelog, writes release
metadata, generates accepted outputs, commits release state to `main`, creates
the tag, and dispatches tag publishing.

The tag workflow publishes release artifacts without pushing branch commits.

## Variants

Boardwright currently uses the inherited KiBot variant names:

```text
DRAFT
PRELIMINARY
CHECKED
RELEASED
```

`DRAFT` and `PRELIMINARY` are useful for early and review builds. `CHECKED` is
intended for reviewed fabrication-ready output. `RELEASED` is intended for
official production releases.

Project defaults live in `.boardwright/project.yaml` and are edited through
Project Info.

## Commands

Useful commands:

```powershell
python -m boardwright status
python -m boardwright validate
python -m boardwright doctor
python -m boardwright review
python -m boardwright accepted
python -m boardwright testbench plan --github-repo OWNER/boardwright-live-test
python -m boardwright source-package --output boardwright-source.zip
python -m boardwright docker-kibot --version 9
```

Run the test suite with:

```powershell
python -m unittest discover -s tests -v
```

See `docs/TESTBENCH.md` for isolated live CI testing in a separate repository.

## README Surfaces

This root `README.md` documents Boardwright itself.

Downstream board-project READMEs are generated from:

```text
boardwright_resources/kibot/resources/templates/readme.txt
```

Generated project READMEs can include board renders, release version, board
revision, dimensions, and release-output guidance. This root README should stay
human-authored and should not be overwritten by generated board-project
content.

## KiCad Template Notes

This repository is also a KiCad project template. It includes worksheets in
`Templates/`, KiBot resources in `boardwright_resources/`, and template
metadata under `meta/`.

The worksheet path follows the KiCad project file. The worksheet image/legal
notice and core project metadata are configured through Boardwright Project
Info.
